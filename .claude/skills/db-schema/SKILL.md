# Database schema

The database schema lives in `packages/backend/src/db/schema/**` (Drizzle ORM). Migrations are generated by `drizzle-kit` into `packages/backend/src/db/migrations/` and are committed to the repo.

## Naming

- **Table names: PascalCase, plural, domain-grouped.** Prefix every table in a domain with the same noun so related tables sort together:
  - `NetWorthEntries`, `NetWorthValues`, `NetWorthAssetCategories`, `NetWorthLiabilityCategories`, `NetWorthOptionCategories`.
- **Column names: camelCase.** Pass the name as the first argument to each column helper so Drizzle quotes it verbatim:
  ```ts
  createdAt: timestamp("createdAt", { withTimezone: true }).notNull().defaultNow(),
  ```
  Do not rely on Drizzle's default snake_case casing for this repo.
- **Enum type names: camelCase, domain-prefixed** (`netWorthAssetType`, `netWorthCurrency`).

## Documentation

JSDoc every table and every column whose purpose isn't obvious from its name. Skip descriptions for `id`, `createdAt`, `updatedAt`, and `name` unless there's something specific to flag.

```ts
/** One net-worth snapshot, keyed to a calendar month. */
export const NetWorthEntries = pgTable("NetWorthEntries", {
  id: uuid("id").primaryKey().defaultRandom(),
  /** Any calendar day inside the target month (day-of-month isn't significant). */
  date: date("date", { mode: "date" }).notNull(),
  createdAt: timestamp("createdAt", { withTimezone: true })
    .notNull()
    .defaultNow(),
  updatedAt: timestamp("updatedAt", { withTimezone: true })
    .notNull()
    .defaultNow(),
});
```

## Standard columns

Every table gets:

- `id: uuid("id").primaryKey().defaultRandom()`
- `createdAt: timestamp("createdAt", { withTimezone: true }).notNull().defaultNow()`
- `updatedAt: timestamp("updatedAt", { withTimezone: true }).notNull().defaultNow()`

## Migrations

1. **Drizzle first.** Edit the schema file(s) under `src/db/schema/` — never write SQL migrations by hand.
2. **Generate.** Run `pnpm --filter backend db:generate`. This creates a new SQL file in `src/db/migrations/` and updates the `_meta` snapshot.
3. **Commit both** the schema change and the generated migration in the same commit.
4. **Apply.** `pnpm --filter backend db:migrate` runs pending migrations against the `DATABASE_URL` in `.env`.
5. **Never hand-edit** a generated migration file. If the generated SQL is wrong, adjust the Drizzle schema and regenerate (after deleting the bad migration if it hasn't been applied anywhere yet).
6. **Regenerate the full-schema dump** with `pnpm --filter backend db:generate-schema`. This runs `drizzle-kit export --sql` into `src/db/__generated__/schema.sql` (committed) — a flat, readable source of truth for the current shape of the DB. Regenerate whenever the Drizzle schema changes.

## Constraints

- **Check constraints** and expression indexes use `sql\`\`` template literals. Name every constraint explicitly (`TableName_column_ck`, `TableName_column_idx`, `TableName_field_uq`).
- Prefer enforcing invariants in the DB even when the resolver validates them — the DB is the source of truth.
